# Контент-ферма: правила игры

Памятка для того, кто делает контент вместо меня. Здесь собрано всё, что важно: форматы, безопасные зоны,
нейминг, кодирование видео, работа с фото и AI-генерацией, музыка, проверка перед сдачей, библиотеки.
Правила взяты из реальных правок клиента. Почти за каждым пунктом стоит переделанная партия.

---

## 0. Главное за минуту

1. **Сначала тесты, потом партия.** Делаешь 2–5 тестов, показываешь и ждёшь явного «делай N штук».
   «А можно сделать 200?» — это вопрос, а не команда запускать.
2. **Текст ТЗ — дословно.** Даже если видишь опечатку, пиши как в ТЗ (можно спросить, но не исправляй сам).
3. **Весь текст лежит в безопасной рамке** (раздел 2). Лицо, глаза и главный объект текстом не закрываем.
4. **Нет айди в ТЗ → айди = 1.** Файлы называем `NNN_1.mp4` / `…_1.jpg`. Слова `noid` не бывает.
5. **Папка начинается с названия приложения:** `app_1234_100`, а не просто `1234_100`.
   Слайды каруселей называем `sort_<слайд>_<номер карусели>_<айди>.jpg`.
6. **Метаданные удаляем всегда:** и у видео, и у JPEG.
7. **Только 1080p.** Исходники 4K сначала один раз переводим в лёгкую 1080p-копию (прокси).
8. **Каждый кадр каждого видео проверен глазами** до того, как ролик кому-то показан.
9. **TikTok- и YouTube-партии уникальные**, а не копии одной и той же (исключения — только если клиент сказал прямо).
10. **В папке сдачи лежат только готовые файлы.** Тесты, кэш, листы проверки и логи — в отдельной рабочей папке (`_work`).

## 1. Форматы

| Что | Холст | Примечание |
|---|---|---|
| Рилс / видео / фото-пост 9:16 | 1080×1920, 30 fps | всегда 1080p |
| Карусель | **1080×1440 (3:4)** | даже если в рефе 9:16; в Flow генерим тоже 3:4 |
| Карусель 4:5 | 1080×1350 | только если ТЗ прямо просит |

## 2. Безопасные зоны (ВСЕГДА)

Интерфейс приложений закрывает края кадра: сверху вкладки, снизу ник, подпись и музыка, справа колонка кнопок.
Любой текст (и всё, что должно читаться: экран игры, логотип, карточка App Store) ставим только внутри рамки:

| Формат | Текст по X | Текст по Y |
|---|---|---|
| **9:16** (1080×1920) | 140–940 (ширина ≤ 800) | 200–1540 px |
| **3:4** (1080×1440) | 180–900 (ширина ≤ 720) | 6–78 % высоты (86–1123 px) |
| **4:5** (1080×1350) | 180–900 | 6–78 % (81–1053 px) |

Для 3:4 отдельно: в правом верхнем углу (x ≥ 86 %, y ≤ 7 %) Инстаграм показывает счётчик «1/6», туда тоже не ставим.

Если текст не помещается мимо лица и интерфейса одновременно: переносим строку, уменьшаем кегль или берём другой
кадр. Под интерфейс текст не ставим никогда.

Проверка (Python, вставить в свой сборщик):

```python
def text_rect(w, h):
    """Безопасная рамка для текста: (x0, y0, x1, y1)."""
    if h / w > 1.6:                                   # 9:16
        return round(w * 140 / 1080), round(h * 200 / 1920), round(w * 940 / 1080), round(h * 1540 / 1920)
    return round(w * 180 / 1080), round(h * 0.06), round(w * 900 / 1080), round(h * 0.78)   # 3:4, 4:5

def check_box(w, h, box):
    """box = (x0, y0, x1, y1) блока текста; пустой список — всё внутри."""
    fx0, fy0, fx1, fy1 = text_rect(w, h)
    x0, y0, x1, y1 = box
    bad = []
    if y0 < fy0: bad.append(f"сверху {y0} < {fy0}")
    if y1 > fy1: bad.append(f"снизу {y1} > {fy1}")
    if x0 < fx0: bad.append(f"слева {x0} < {fx0}")
    if x1 > fx1: bad.append(f"справа {x1} > {fx1}")
    return bad

# для PNG-оверлея с прозрачностью: check_box(W, H, img.getbbox())
```

Перед партией проверяем **все** раскладки (у каждого клипа своя), а не один кадр.

## 3. Нейминг и айди

- **Айди.** Если ТЗ его даёт, ставим его. Если нет, айди = **1** (и для видео, и для каруселей).
  Номер проекта айди не является, если ТЗ этого не говорит.
- **Видео:** `<номер>_<айди>.mp4` → `001_1.mp4`, `002_1.mp4`… (можно с префиксом приложения: `app_001_1.mp4`).
- **Карусели:** все слайды всех каруселей лежат **одной плоской папкой** с именами
  `sort_<слайд>_<номер карусели>_<айди>.jpg`.
  - Пример: карусель №7, слайд 3, без айди в ТЗ → `sort_3_7_1.jpg`.
  - Партия 100 каруселей по 7 слайдов = 700 файлов от `sort_1_1_1.jpg` до `sort_7_100_1.jpg`.
- **Папки сдачи:** `<приложение>_<проект>_<кол-во>_<вариант>`.
  - Примеры: `app_1234_100_8s`, `app_ghost_TT_100`, `app2_YT_200`.
  - Приложение пишем всегда, потому что папки уходят клиенту пачками и голый номер ни о чём не говорит.
- **Имена людей в кадре** (ники, имена в чатах, исполнители, имена файлов на экране) — только
  международные/американские: Mia Carter, Ava Reed, Jake Miller. Русская фамилия в кадре — это брак, кадр переделываем.
  Скачанные со стоков файлы переименовываем, у mp3 стираем теги.

## 4. Видео: кодирование и обработка

Машина: Windows, RTX 3070 8 GB, i7-12700. ffmpeg нужна сборка с NVENC (например, BtbN или gyan full build).

**Финальные ролики** кодируем на видеокарте, лёгким файлом и без метаданных:

```bash
ffmpeg ... -c:v h264_nvenc -preset p5 -rc vbr -cq 27 -maxrate 6M -bufsize 12M \
  -pix_fmt yuv420p -colorspace bt709 -color_primaries bt709 -color_trc bt709 \
  -c:a aac -b:a 160k \
  -map_metadata -1 -fflags +bitexact -flags:v +bitexact -flags:a +bitexact \
  -metadata:s:v:0 encoder= -metadata:s:v:0 handler_name= -metadata:s:a:0 handler_name= \
  -movflags +faststart out.mp4
```

- **Промежуточный кэш** (прокси, нарезки) кодируем в cq 14–19. Финал — cq 27 с maxrate 6M, иначе файлы
  выходят тяжёлыми (было 49 МБ на 28 с, клиент ругался).
- **Прокси 1080p — обязательно.** Каждый исходник больше 1080p или 60 fps один раз переводим в 1080×1920
  30 fps и дальше собираем только из этой копии. Партия в 150 роликов тогда идёт 2–3 минуты, а не полчаса.
- **iPhone HLG** (бледная картинка; `ffprobe` показывает `color_transfer=arib-std-b67`) перед масштабированием тонмапим так:
  `zscale=t=linear:npl=120,format=gbrpf32le,zscale=p=bt709,tonemap=tonemap=hable:desat=0,zscale=t=bt709:m=bt709:r=tv`
- **Параллельность:** не больше 5–6 процессов ffmpeg с декодом на процессоре. Декод через CUDA (`-hwaccel cuda`)
  ставим только на 1–2 тяжёлых 4K-входа и держим не больше 3 процессов: при 8 процессах × CUDA видеокарта
  переполнилась и комп ушёл в синий экран.
- **Тяжёлые фильтры** (сильный blur, removelogo, попиксельные выражения) гоняем на уменьшенной копии кадра.
  Размытие фона делаем так: уменьшить до ~96 px → boxblur → увеличить обратно.
- **Музыка:** громкость задаём постоянным усилением, без loudnorm на треке с дропом, иначе дроп сглаживается.
  Склейки ставим в бит (`librosa.beat.beat_track`).

### Проверка каждого кадра (обязательно)

Клиент смотрит ролики покадрово. Секундная вспышка Пункта управления iOS посреди «геймплея» — это брак всей партии.

1. **Чужие записи** (геймплей, нарезки фильмов): прогоняем исходник детектором на 30 fps (сравнение кадра с соседями,
   элементы интерфейса на месте?) и берём только чистые интервалы. Из фильмов берём куски только внутри одной сцены,
   без склеек.
2. **После рендера** собираем контакт-лист каждого тестового ролика (кадры раз в 0.2–0.25 с), а места склеек
   и появления плашек смотрим на всех 30 кадрах в секунду.
3. Ролик с ошибкой убираем из папки сдачи.

Скрипт контакт-листа:

```python
import subprocess, sys
import numpy as np
from PIL import Image, ImageDraw

src, fps, out = sys.argv[1], float(sys.argv[2]), sys.argv[3]
tw, th = 120, 213
raw = subprocess.run(["ffmpeg", "-v", "error", "-i", src, "-vf", f"fps={fps},scale={tw}:{th}",
                      "-f", "rawvideo", "-pix_fmt", "rgb24", "-"], capture_output=True).stdout
fr = np.frombuffer(raw, np.uint8).reshape(-1, th, tw, 3)
cols = 10
sheet = Image.new("RGB", (cols * tw, -(-len(fr) // cols) * (th + 14)), "white")
d = ImageDraw.Draw(sheet)
for i, f in enumerate(fr):
    x, y = (i % cols) * tw, (i // cols) * (th + 14)
    sheet.paste(Image.fromarray(f), (x, y + 14))
    d.text((x + 2, y), f"{i / fps:.2f}", fill=(200, 0, 0))
sheet.save(out, quality=85)
# python sheet.py video.mp4 4 sheet.jpg
```

## 5. Текст на кадре

- **Шрифт:** TikTok Sans (бесплатный, OFL). Белый текст с **ровной** чёрной обводкой со всех сторон,
  толщина ≈ 6.5 % кегля. Обводку рисуем, например, через `stroke_width` в Pillow; смещённая тень вместо
  обводки даёт контур толще снизу справа, клиент такое не принимает.
- Белый текст **без** обводки (если так в рефе) получает мягкую тень: размытие 5, 75 % чёрного, сдвиг (0, 3).
- **Эмодзи** — только Apple-эмодзи картинками, вставленными в строку. Системные виндовые выглядят не так.
- **Переносы строк по смыслу**, вручную: одна фраза на строку. Автоперенос по ширине, который рвёт фразу,
  клиент не принимает. Название приложения не разрываем на две строки. Кегль берём максимальный, при котором ни одна
  строка не переносится сама и блок влезает в зону. Исключение: формат «скриншот комментария/твита»
  переносится просто по ширине, как настоящий пост.
- Текст лучше крупный. Когда чтобы обойти лицо, пришлось бы уйти ниже ~40 px, лучше крупно и пусть закрывает
  (в форматах «текстволл» клиент так и просил).
- **Тайтл/хук — всегда сверху** (~0.2–0.25 H), **субтитры к голосу — снизу** (~0.72 H). Не наоборот.
- Плашки на лицах ставим ниже подбородка и жестов.
- Видео не сдвигаем и не добавляем сверху «размытую полосу», чтобы освободить место под текст: клиенту такое
  не нравится. Кадр оставляем как есть.

## 6. Монтаж и удержание

- Самый сильный кадр — в первые 0.5–1 с. Каждая секунда должна давать причину смотреть дальше.
- Говорящая голова: вырезаем паузы (джамп-каты), на каждой склейке чередуем масштаб ~100 % / 112 %.
  Конец дубля режем сразу после последнего слова, до движения руки к телефону.
- **Реакция совпадает с текстом.** Окна лица подбираем по кадрам под смысл фразы, случайный сдвиг не годится.
  Если в тексте «шок», на лице должен быть шок, без моргания и без середины слова.
- Мемы, стикеры и эффекты добавляем только туда, где их ставит раскадровка ТЗ.
- Синтетические звуки (whoosh/boom) клиенту не зашли. Голос + музыка, мягкий «поп» на появлении карточки — ок.
- **Карточка App Store поверх видео:** тёмная шапка страницы приложения (иконка, название и подзаголовок
  на языке ролика, кнопка «Get» или её перевод), скруглённые углы, по центру, низ около 1525 px. Страница стора должна быть
  видна на экране не меньше ~1.9 с, иначе её не успевают прочитать.
- Карусели и видео из одних фото: одинаковый seed → видео N и карусель N получают один и тот же набор фото.

## 7. Фото: отбор (Pinterest и т. п.)

Требования очень строгие, это правило клиента «навсегда»:

- **Оцениваем всё:** девушку (привлекательность), позу, ракурс, резкость, свет, фон, цвет, композицию, настроение.
  Если фото выглядит дёшево, так и говорим.
- **Сразу в брак:** серые плитки ванных, лифты, офисы, тёмный или жёлтый свет, блик вспышки в зеркале, бардак,
  мыло, низкое разрешение, вотермарки, неудачный кроп, сток, каталог на белом, коллажи, ИИ-фото.
- **Берём:** мягкий дневной свет, чистые красивые интерьеры, удачные позы, резкие детали, гармоничная палитра.
- **Меньше, но лучше:** 3 лучших на слайд достаточно.
- **Порог качества:** кроп 3:4 шириной ≥ 900 px; резкость (дисперсия Лапласиана на 540×720) ≥ 180.
- **Поиск** как у обычного человека: 1–3 коротких запроса («outfits», «ootd», «<вещь> mirror selfie»,
  «<вещь> street style»). Сортируем по популярности (сохранения, лайки, от ~300). Ветку расширяем через
  «Похожие пины» на лучших находках.
  - Если в рубрике конкретная вещь, сначала гуглим, какие модели и бренды сейчас реально популярны.
  - Пины с заголовками-листиклами («30 Best…», «How to style…», «outfit ideas») — это ИИ-фермы, пропускаем.
- **B-roll под реф:** совпадать должен ракурс и «кто снимает», а не только тема. Например, девушка снимает
  с пассажирского сиденья, парень сам себя на телефон в зале. Без промо-монтажа, текста и рекламных съёмок.
- **Селебы на обложках:** только свежие эстетичные кампании и эдиториалы (2026), не старые фото с красной дорожки.
- **Одна героиня и одна «фотосессия» на всю карусель:** то же лицо, тот же свет, та же палитра на всех слайдах.

## 8. AI-генерация (Google Flow / Veo)

- **Один промпт на слайд.** Уникальность партии делаем при сборке (кроп, цвет, позиция текста), а не 4 вариантами.
- **Девушки:** красивые, ухоженные, чистая ровная кожа, лёгкий естественный макияж, аккуратные волосы.
  **Никогда** не пишем «tired», «no makeup», «messy», «pores», «freckles», «imperfect skin»: модель превращает её
  в замученную и некрасивую. Грусть передаёт текст, а не её внешность.
- **Живость** даёт камера, а не внешность: «Unedited iPhone snapshot», один конкретный бытовой момент,
  обжитая комната (перечислить предметы), свет из окна с одной стороны, лёгкий шум, слегка криво и не по центру,
  всё резкое, без боке. Слова «modern / cozy / aesthetic / beautiful» не пишем: они делают картинку ИИшной.
- Без «старого деревянного стола», винтажного реквизита и предмета посреди пустого стола.
- **POV / от первого лица:** телефон в одной руке, в кадре максимум одна рука и рукав. Не «вижу свои руки сверху»,
  не «мой телефон на столе» (им же снимают). Истории «я/мне» снимаем от её глаз, не со спины.
- Если в референсе есть человек, Flow копирует его лицо и позу. Поэтому для комнаты даём кадр **без людей**,
  а позу берём с реального популярного селфи из Pinterest («Image 2 only for pose»).
- Экран телефона в кадре: просим пустой белый экран, а настоящий скрин накладываем потом с перспективой.
- **Veo (видео из картинки):** стартовый кадр показывает *до* события (реквизит виден, но не используется),
  в промпте одно событие около 1 с + реакция. Перед выбором куска проверяем, нет ли резкого скачка позы через ~0.4 с.
- Мужчины/артисты тоже стильные и привлекательные, в эстетичных комнатах. Никаких «инди-бомжей» в худи и бардака.

## 9. Музыка

- Звук из рефа, если ТЗ так говорит. Иначе подбираем под настроение: грустные текстволлы — грустный трек,
  истории — «жизненный», юмор — весёлый. Каждый трек слушаем с нашим текстом, прежде чем ставить.
- TikTok-звук получаем со страницы видео: в данных страницы лежит ссылка `music.playUrl`.
  Закрытые аккаунты не тянем. Бот-проверки, капчи и чужие логины не обходим.

## 10. Процесс по шагам

1. Читаем ТЗ: тексты (дословно), длительность, количество TT/YT, айди, реф.
2. Скачиваем исходники в `downloads/<проект>/`. 4K/HLG сразу переводим в 1080p-прокси.
3. Отсматриваем исходники листами (0.25 с), выбираем окна под каждую фразу.
4. Пишем сборщик (Python + ffmpeg): план партии с seed, перебор сочетаний (клип × окно × зеркало × вариант)
   плюс случайные мелочи (сдвиг старта, зум 1.00–1.06, яркость ±0.02, насыщенность 1.0–1.1), чтобы все ролики
   отличались.
5. Тест 2–5 штук → проверка каждого кадра и безопасных зон → показываем → ждём «делай N».
6. Партия → проверка: длительность, разрешение, уникальность md5, метаданные, выборочные листы.
7. JPEG прогоняем через очистку метаданных (код ниже).
8. Сдаём папку `<приложение>_<проект>_<N>` только с готовыми файлами.

Очистка JPEG без пересжатия (выкидывает EXIF/XMP/ICC/комментарии):

```python
import sys
from pathlib import Path

def strip(data: bytes) -> bytes:
    out, i = bytearray(b"\xff\xd8"), 2
    while i < len(data):
        m = data[i + 1]
        if m == 0xDA:                       # дальше сама картинка — копируем до конца
            out += data[i:]
            break
        n = int.from_bytes(data[i + 2:i + 4], "big")
        if not (0xE0 <= m <= 0xEF or m == 0xFE):
            out += data[i:i + 2 + n]
        i += 2 + n
    return bytes(out)

for f in Path(sys.argv[1]).rglob("*.jp*g"):
    f.write_bytes(strip(f.read_bytes()))
# python strip_jpeg_meta.py output/app_1234_100
```

## 11. Окружение и библиотеки

- **Python 3.11** (на 3.13+ часть библиотек не ставится), виртуальное окружение `.venv`.
- **ffmpeg 7–8 с NVENC**, лежит в PATH.
- Шрифты: TikTok Sans (Bold/SemiBold), Inter (для интерфейсов вроде App Store), Bebas Neue (крупные заголовки).

```bash
python -m pip install pillow pillow-heif numpy scipy opencv-python scikit-image librosa soundfile requests yt-dlp playwright
```

Дополнительно:

```bash
python -m playwright install msedge
```

Для чего что:

| Библиотека | Для чего |
|---|---|
| pillow, pillow-heif | текст, плашки, слайды каруселей, фото с iPhone (HEIC) |
| numpy, scipy | маски, проверки кадров, детекторы |
| opencv-python | трекинг объекта (родинки и т. п.), склейки, резкость (Лапласиан) |
| scikit-image | сравнение кадров (SSIM) |
| librosa, soundfile | биты и дропы в музыке, нарезка звука |
| playwright | рендер HTML-экранов (имитация интерфейса приложений) в PNG |
| yt-dlp | скачать референсы по ссылке |
| mediapipe (по желанию) | положение лица/подбородка, чтобы текст не лез на лицо |
| simple-lama-inpainting + torch (по желанию) | стирание вшитых подписей с чужих видео |
